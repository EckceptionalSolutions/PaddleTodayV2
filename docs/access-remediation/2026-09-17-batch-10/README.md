## Repeatable steps for a weaker model

1. Read the operator runbook, this README, frozen `selection.json`, and `review.json`. Work ranks 121–130 in order. Do not replace difficult sites. Treat cached audit distances as triage clues, not proof that a point is wrong.
2. Read `source-metadata.json`. Use only snapshots marked `acceptedAsEvidence`; failed retrievals are leads that need another source. Recheck manager sources for the named waterbody, current public access, bank, restrictions, and route role. Do not infer public launch access from a nearby river line, campground, address, bridge, trail, parking lot, or park boundary.
3. For every stored point, state what it represents: water entry, ramp, dock, end of a carry, required check-in, trailhead, or broader access-area anchor. If a manager source establishes the site but does not publish its wet-edge coordinate, retain the honest area anchor and remove any wording that claims exact entry precision. Never snap a point to the nearest water line.
4. Compare each proposed correction to the exact feature ID and attributes in the official source. Check coordinate order (ArcGIS `x` longitude, `y` latitude), correct river and dam side, access status, and route direction. Record any unresolved route continuity separately from the coordinate decision.
5. If a required endpoint is not verified, keep its source record, document what remains unknown and what evidence would reopen it, and add every dependent route to `src/data/route-access-review-holds.ts`. If a corrected endpoint depends on a geometry that cannot be regenerated and checked, withhold those routes too. Do not clear a hold just because a source coordinate is available.
6. Before editing, copy and SHA-256 each changed file. Save official-source snapshots and retrieval outcomes in the cache directory, with hashes and URLs in `source-metadata.json`. Keep `selection.json` frozen. Failed source retrievals must remain unaccepted.
7. Regenerate `src/data/generated/withheld-route-slugs.ts`, then run `node docs/access-remediation/2026-09-17-batch-10/verify.mjs`. Follow the runbook's typecheck, fresh audit, tests, route-specific geometry, geometry audit, catalog assembly and registry order. Never assemble a catalog with stale changed-route geometry. If a missing package blocks a check, save the exact error in `validation.json`; keep dependent routes withheld and do not claim the check passed.
8. Before finishing, confirm all ten frozen ranks have one decision, all changed occurrences use the intended coordinate, all six new holds appear in the generated manifest, and backups and accepted source snapshots match their hashes. Update `validation.json` with commands and observed outcomes rather than expected outcomes.
