## Repeatable steps for a weaker model

1. Read the operator runbook, this README, frozen `selection.json`, and `review.json`. Work ranks 131–140 in order. Do not replace difficult sites. Treat cached audit offsets as triage clues, not proof of a bad coordinate.
2. Read `source-metadata.json`. Use only snapshots marked `acceptedAsEvidence`; the two failed HTTP 404 retrievals remain unaccepted. Verify current managing-agency evidence for the waterbody, public access rights, actual bank, route role, and conditions. A nearby campground, confluence, trailhead, bridge, road, or river line does not prove a lawful launch or take-out.
3. For each saved point, state what it represents: boat-ramp site GPS, dock-address geocode, parking area, access corridor, or water entry. If a manager confirms the site but does not publish a wet-edge coordinate, preserve an honest site anchor and remove any exact-edge claim. Never snap to the nearest mapped water line.
4. Compare any proposed correction with the official feature ID and attributes. Check coordinate order (`x` is longitude, `y` latitude), named river, dam side, access status, route direction, and whether a point is a parking/carry anchor rather than the river landing. Do not substitute a nearby access without checking route continuity.
5. If a required launch or take-out is unverified, preserve its source record and list what evidence would reopen it. Add every dependent route to `src/data/route-access-review-holds.ts`, regenerate the withholding manifest, and keep it held until a current land manager or a defensible official map verifies lawful access and location.
6. Before editing, copy and SHA-256 every source file. Preserve accepted source snapshots and failed retrieval outcomes in `source-metadata.json`; keep `selection.json` frozen. This batch's backups are under `node_modules/.cache/access-batch-11/before-source/`, and their hashes are recorded in `before-file-hashes.json`.
7. Regenerate `src/data/generated/withheld-route-slugs.ts` and run `node docs/access-remediation/2026-09-17-batch-11/verify.mjs`. Then follow the runbook's typecheck, fresh audit, tests, geometry generation, geometry audit, catalog assembly, and registry order. Do not publish or assemble from stale route geometries. Record exact blockers in `validation.json` and keep dependent routes withheld.
8. Before finishing, confirm every frozen rank has one decision, all repeated occurrences use the reviewed labels and notes, both new holds are in the generated manifest, source snapshots and backups match their hashes, and validation outcomes describe commands actually run.
