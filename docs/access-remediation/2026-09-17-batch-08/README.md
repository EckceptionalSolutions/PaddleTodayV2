## Repeatable steps for a weaker model

1. Read the repository [runbook](../../access-point-remediation-runbook.md), this README, `selection.json`, and `review.json`. Keep all ten frozen physical sites, including the combined Johnson queue entries at ranks 101 and 102.
2. For each point, establish what its coordinate represents before editing: ramp, carry-in, access-area pin, parking, campground/facility, rapid scout, bridge, or optional bailout. Do not move a point to the river centerline simply because the audit reports an offset.
3. Prefer current manager sources for public status and manager GIS/maps for coordinates. Record their exact feature IDs, published coordinate fields, uncertainty, access role, retrieval date, response status, and hash. Keep failures in the log but never treat them as evidence.
4. Search route source and trip-detail data for all copies. If trip details derive from a route object, document that dependency. Remove unsupported optional access markers from both copies while retaining route hazard warnings. Change a required endpoint to an explicit unverified label and withhold its route when lawful water entry is not established.
5. Regenerate the withheld-route manifest after every hold change. Run the batch verifier and applicable type/test/audit/geometry/catalog steps. Keep affected routes withheld whenever a corrected endpoint cannot be checked against generated geometry and the served catalog.
6. Do not use a stale cached audit to regenerate the access registry. If the full audit or geometry tools are blocked by missing dependencies, record the exact package and leave dependent routes held.
