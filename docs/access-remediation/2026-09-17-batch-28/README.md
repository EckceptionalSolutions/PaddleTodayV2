# Public access-point review: batch 28

This batch applies the [access-point remediation runbook](../../access-point-remediation-runbook.md) to the first ten distinct physical sites in the **public-route** review queue, in frozen priority order. The queue was created from `listRivers()` and excluded sites reviewed in batches 1–27. The cache-only selection had 2,761 public routes and 6,082 endpoint occurrences; the full refresh and its coverage checks are recorded in the audit files beside this review.

The review found two defensible coordinate improvements: the Charenton TECHE dock was moved to its named mapped dock feature, and the Loreauville TECHE dock was moved to the coordinate published by the parish visitors bureau. Those shared locations changed 12 endpoint occurrences across 11 unique routes. Targeted post-change audits reported each corrected dock occurrence within 100 feet of mapped water; one Loreauville route occurrence still has incomplete hydrography coverage, so its mapped-water distance is provisional. Eight other sites have adequate public-access identity evidence, but only an access-area, check-in, parking, or carry anchor can be supported; those coordinates remain explicitly classified as access anchors rather than surveyed wet-edge points. The existing Hudson Gorge and Noblewood controls were also corrected from `authoritative-water-entry` to `authoritative-access-anchor`. The audit now selects the closest matching official control, preventing a nearby wet-edge control from overriding an exact parking/carry coordinate. No site in this batch was found to be invalid or sufficiently unverified to reject, and no new route hold was needed. Existing route holds remain intact.

The Lower Cato Falls review corrected an unsafe implication in the route instructions: the county confirms steep stairs to the river, but no source reviewed here establishes a bypass carry around the falls. The route now says to scout first and not launch unless the group can safely run the rapid.

## Repeatable steps for the next model

1. Read `docs/access-point-remediation-runbook.md`, inspect `git status --short`, and preserve pre-existing changes. Use `git diff --ignore-space-at-eol` when line-ending noise obscures the actual edits.
2. Run `npm run routes:audit:access-quality -- --cache-only` to see whether cached hydrography exists. Treat this only as candidate selection. Run a separate full `--refresh` audit before deciding whether offsets are real, and verify the report covers every route returned by `listRivers()`.
3. Select distinct physical sites from the public-route queue, retain all affected route occurrences, and freeze the site list before research. Do not substitute easier locations after research begins.
4. For each site, establish identity and current public use from the manager or trail operator. Then distinguish its published coordinate from an exact ramp, dock, stair, bank, parking or check-in location. Do not copy a map viewport or substitute a nearby water point.
5. Correct coordinates only when a source locates the same intended public access. If current evidence verifies a public, usable site and an actionable arrival/carry location but does not georeference its wet edge, retain it only as a clearly scoped access anchor with honest uncertainty and arrival instructions. If a route depends on a precise entry (for example, choosing a side of a dam), or public permission/access/continuity cannot be established, reject the access and hold every dependent public route.
6. Update every shared route endpoint, provider control, route note and trip caveat that depends on the site. Preserve unrelated route holds and public/withheld inventory.
7. Refresh every changed route against hydrography. Inspect waterbody, distance and source coverage; an offset is a prompt for research, not proof that the access is wrong.
8. Regenerate changed route geometry first, then assemble the catalog, audit geometry, regenerate the overview and withholding outputs, and generate the access registry from the complete refreshed audit.
9. Run the batch verifier, route typecheck, catalog audit and relevant access tests. Save failures and environmental blockers without claiming a pass.

The access registry applies a stricter facility-identity match than the audit’s broad name match. When source-backed review establishes that a curated route label and an official control identify the same site, add that exact route label as a provider alias; do not weaken the shared identity matcher. Keep `waterEntryCoordinate` empty unless a source separately locates the actual wet edge. The batch verifier checks these distinctions for the Charenton and Loreauville docks and the Outer Gooley and Noblewood public anchors.

`selection.json` preserves the frozen candidate order and original queue measurements. `review.json` records the site-level decisions and affected routes; `source-metadata.json` states what each source establishes and what it does not. `validation.json` records the completed refresh, regeneration and checks. `verify.mjs` checks the current source inventory and the safeguards that matter for this batch.
