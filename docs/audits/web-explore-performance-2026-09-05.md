# Web Explore performance — September 5, 2026

Implemented viewport filtering, progressive geometry loading, and MapLibre-rendered score badges on the web Explore page. This builds on the earlier marker reconciliation and geometry caching changes.

## Behavior

- The map selects routes intersecting its bounds plus a 15% buffer. Offscreen top-ranked results are no longer kept on the map. Full route bounds account for bends and routes crossing the view, and unchanged route subsets retain their identity.
- The existing result limit and “show more” control apply to the current map area. The full filtered card list remains available; choosing a card outside the view moves the map to it.
- A generated overview contains simplified, endpoint-preserving river traces and full-resolution bounds and anchor points. Its current size is approximately 1.09 MB. Missing canonical assets continue to use access-coordinate fallbacks.
- At zoom 8 and above, detail is requested for visible routes, with selected routes first, a maximum queue of 200 routes, and four concurrent requests. Camera movement cancels old requests; requests for the new view resume when movement finishes. Failed or malformed detail responses retain the overview and have a retry cooldown.
- MapLibre circle and text layers draw the score badges. Static, visually hidden buttons retain keyboard/screen-reader interaction. Mouse clicks on badges and keyboard selection open the same route popups, and the focused/selected badge is highlighted.
- Detail arriving later updates line sources without rebuilding unchanged rows or closing an open popup. Style/source recreation restores the overlays.

The overview is regenerated by `predev`, `prebuild`, and `prebuild:app`. It can also be regenerated with `npm run routes:overview:generate`.

## Real-map measurements

The profile uses real MapLibre GL JS 5.3.0, the actual basemap, route metadata, and canonical geometry. Scores are fixed fixtures so server/gauge refreshes do not confound rendering. Measurements use Chromium headless, a 1280 × 900 viewport, four 800 ms camera animations, and two-second sampling windows against the local development server.

| Measurement | Before this change | Final run |
| --- | ---: | ---: |
| Decoded geometry response bodies for the sequence | 32,651,387 bytes | 1,298,761 bytes |
| Positioned HTML map markers, regional view | 740 | 0 |
| Positioned HTML map markers, local view | 815 | 0 |
| Long tasks over 50 ms across the four windows | 54 | 5 |
| Regional zoom, p95 frame interval | 83.3 ms | 50.1 ms |
| Local zoom, p95 frame interval | 83.3 ms | 50.1 ms |
| Local pan, p95 frame interval | 66.7 ms | 50.0 ms |
| Return to regional view, p95 frame interval | 83.4 ms | 66.6 ms |

Geometry payload was approximately 96% smaller for this sequence. The original profile identified marker transform/opacity updates among the prominent JavaScript costs. The final run has no positioned HTML map markers, and the local pan recorded no long tasks. A click on a rendered badge was also verified against real MapLibre, and the resulting popup was visually inspected.

These are diagnostic measurements, not a production FPS guarantee. Headless rendering, the development toolbar, tile timing, and concurrent machine activity affect frame intervals. The route inventory was also being expanded during the work: the baseline has 2,052 routes and the final run has 2,062. Repeated final runs varied, including 33–50 ms p95 local pan intervals; the table uses the latest complete run, not the fastest.

## Validation

- 53 focused unit tests passed, including viewport intersections, stable subsets, wrapped longitude bounds, simplification, request cancellation/concurrency, late overview/detail races, malformed responses, cache invalidation, and map source lifecycle.
- All nine Explore desktop browser checks passed across the focused runs.
- The 210-route performance/interaction regression and delayed-overview regression passed on desktop Chromium and an emulated iPhone. They cover offscreen removal, unchanged-row reuse, zoom modes, real score-layer feature counts, click and keyboard popups, score refresh, filters changing geometry under the same river key, late anchor updates without closing popups, and style restoration. No all-state geometry requests are made.
- `npm run build:app` and the shared-behavior/generated-script checks passed.

The approach follows MapLibre's guidance on reducing and simplifying source data and limiting detailed rendering: [large-data performance guide](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/).
