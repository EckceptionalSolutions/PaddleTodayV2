## Completed in this pass

- **AUD-01:** Explicit `scoreEligibility: planning` is preserved during enrichment; scoring indexes use one shared eligibility predicate; reviewed direct planning routes remain public planning coverage.
- **AUD-02:** Stored summary, weekend, group, and detail snapshot reads filter through the current public route index; public detail requests return 404 before consulting cached storage.
- **AUD-03:** Stale or degraded telemetry downgrades affirmative readiness to `watch`; mobile persisted query hydration is limited to the two-hour snapshot SLA.
- **AUD-04:** Malformed request targets and invalid Host headers are rejected with a bounded 400 response; valid routing uses a fixed internal URL base instead of trusting the client Host value.
- **AUD-05:** Release checks include API-contract/API-client/geo/trip-pack/mobile typechecks, all workspace test suites, scoring invariants, route safety, route data, geometry, gallery, and production build checks. Safety evidence is read from the generated audit rather than hard-coded, whose reports now use atomic replacement with bounded retries. The latest consolidated gate run passed every check with no skipped scopes.
- **AUD-07:** Planning routes in group serialization receive an explicit `null` weather argument, avoiding array-index leakage.
- **AUD-08:** Every rendered homepage freshness node is updated; the global mobile search control has an accessible name.
- **AUD-09:** Forwarded client headers are honored only for configured trusted proxies; admin session creation is rate limited; production admin cookies are `Secure`; API and static responses emit baseline browser security headers and production HSTS.
- **AUD-10:** Contribution photos are decoded with `sharp`, pixel-limited, orientation-normalized, resized, re-encoded as JPEG, and stripped of metadata before storage; the admin API can remove a submission, its source files, index entry, and approved derivatives. Retention windows and deletion operations are documented in [`contribution-retention-policy.md`](../contribution-retention-policy.md).
- **AUD-11:** API and snapshot-worker deployment installs use lockfiles and `npm ci`; the API no longer installs dependencies during startup; `sharp` is a runtime dependency.
- **AUD-12:** Route data audit scans the complete scored-plus-planning inventory, reports planning-only findings separately, and prints reconciled population counts (1,953 inventory, 1,166 scored, 787 effective planning, 1,910 public catalog, 1,878 indexed, 32 withheld). Same-launch loops and round trips are recognized as distinct itineraries when endpoint coordinates intentionally match; one-way duplicate checks remain active. Planning-only distance and mileage-to-anchor assertions now use an explicit source-aware deferral policy: map/chart/tide/condition-controlled labels, staged multi-day descriptions, and planning access-anchor comparisons remain visible with route IDs, evidence, and reasons until a scored-route source review resolves them. Scored-route checks remain blocking.
- **AUD-13:** Expo push delivery has a timeout; Azure has a scheduled alert for missing or stale snapshot-job successes.
- **AUD-14:** `npm run snapshots:capacity` measures producer bytes, gzip/Brotli transfer bytes and savings, route count, average route size, largest route size, and budget headroom when a local snapshot is available.
- **Calibration context:** Scoring outcome submissions now preserve the decision policy revision and evidence age, and the admin review card displays both alongside the observed verdict. The existing calibration model still reports threshold/source segments and warns when the approved sample is small.
- **Funnel context:** Route analytics now attach score eligibility (`scored` or `planning`) and, after the first detail response, readiness and live-data state. Weekly funnel reporting can therefore separate route discovery, views, saves, directions, and reports by route type and data freshness without collecting precise location.
